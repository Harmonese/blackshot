# 原生截图交接原型与验证记录

## 当前入口

```sh
./Experiments/NativeScreenshotBridge/validate.sh --self-test
./Experiments/NativeScreenshotBridge/validate.sh --capture
./Experiments/NativeScreenshotBridge/validate.sh --clipboard
./Experiments/NativeScreenshotBridge/validate.sh --inspect /absolute/path/to/native-capture.png
```

`validate.sh` 独立编译生产代码中的捕获、反色和 XPC 桥接模块：

- `--capture`：系统选区／窗口截图 → 反色 → 系统原生缩略图；也支持在选区完成时按 Control 改走剪贴板。
- `--clipboard`：模拟带 Control 的快捷键，启动时指定复制；完成后替换为反色图片。
- `--inspect`：读取系统原始截图文件的扩展属性，打印真实区域、DPI 缩放和显示器信息。不传回合成坐标。
- `--self-test`：验证 RGB、透明/半透明像素、尺寸、DPI、损坏输入、恢复缓存过期/替换/重启、快捷键编码与 Carbon 冲突回滚。

交互测试输出反色图片的临时路径，用于和系统保存或复制出的图片核对。系统保存位置和缩略图设置生效；不修改这些设置。程序等待 30 秒并不延长系统缩略图停留时间，退出码也不代表原生保存成功。

原先的 `run.sh --demo` / `--file IMAGE` / `--capture` 和 `main.m` 保留为历史协议探针。该探针使用合成图片位置和固定缩放，**不能用于验证真实截图元数据**；真实截图请使用新的 `validate.sh`。

## 内部协议及边界

生产协议集中在 `Blackshot/NativeScreenshotBridge.m`：XPC 服务 `com.apple.screencaptureui`，`msg = UInt64(20)`，`img` 图片字典数组（`dta` PNG、`frm` 区域、`sca` 缩放、`did` 显示器），以及 `uti/shd/cpt/tbr/tim` 字段。

交接结果区分“已提交到传输层／明确失败／不确定”，没有可靠的原生 UI 或保存成功回执。`Connection interrupted` 可发生在图片成功展示后；不自动重试，不自动保存第二份。仅保留最近一张反色结果供用户恢复。

无系统进程注入、系统文件修改、私有授权伪造或安全保护绕过。不要直接启动 `screencaptureui.app`：本机直接启动曾被系统 Launch Constraint 拒绝；应通过系统提供的 XPC 按需启动路径。
